## New Features & Practical Usage

### `--plugin-dir` now manages an entire plugin folder dynamically (v2.1.265)

**`--plugin-dir` can now point at a single folder containing multiple plugins at once.** **Any subfolder with a manifest loads as its own separate plugin, and adding or removing subfolders while a session is running is picked up immediately.**

```bash
claude --plugin-dir ./team-plugins
# ./team-plugins/linter-helper/plugin.json
# ./team-plugins/deploy-checker/plugin.json
# Each subfolder with a manifest loads as a separate plugin,
# and adding or removing folders mid-session takes effect instantly, no restart needed
```

**For teams distributing multiple plugins together, or testing different plugin configurations per project, this lets you manage plugins at the folder level instead of specifying `--plugin-dir` one at a time.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Developer Workflow Tips

### Improved `/workflows` agent detail view — see subagent progress at a glance (v2.1.265)

**The `/workflows` agent detail screen now shows whether each individual tool call is running, failed, or complete, and if a subagent maintains its own task list, that list is displayed alongside it.** **Pressing Enter expands the listed tool calls so you can inspect their inputs and results directly.**

**If you're running multiple agents in parallel with the Workflow tool, this screen alone lets you track progress without digging through logs to figure out where something stalled or failed.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### A skill that stops coding agents from stalling before they answer — I-have-ADHD (9/9)

**A custom skill designed to make coding-assistant replies action-first, replacing long preambles with an immediately actionable task and a numbered procedure.** **Ten response rules suppress tangential explanation, force the assistant to restate its current state every reply, and require ending on exactly one concrete next step.**

**If Claude Code's tendency to pad answers with long background explanations bothers you, this approach of locking response rules into a skill itself is worth referencing for your own CLAUDE.md or custom skills.** [GeekNews](https://news.hada.io/topic?id=33374)

## Security & Limitations

### v2.1.265 regression blocked gateway/proxy setups for a day, fixed in v2.1.266 (9/8)

**The undocumented environment variable `CLAUDE_CODE_USE_GATEWAY` used to be ignored unless both `ANTHROPIC_BASE_URL` and `ANTHROPIC_AUTH_TOKEN` were set, but v2.1.265 started forcing Cloud gateway login based on this variable alone.** **As a result, any LLM gateway or proxy setup that had this variable set alongside an API key, `apiKeyHelper`, or a custom auth header saw every request fail with a "Not signed in to the Cloud gateway" error.**

**v2.1.266, released the same day, reverted the variable to being ignored on its own again, and updating alone restores normal behavior with no configuration changes needed.** **Teams running Claude Code behind their own LLM gateway or proxy should confirm they've updated to v2.1.266 or later, since deploying v2.1.265 even briefly could have blocked all requests.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Claude service status — no new incidents since 9/3, all services operational

**A direct check of the official status.claude.com** shows **no new incidents registered as of 9/9 since the 9/3 incident (elevated error rates across Claude Mythos 5.1, Fable 5.1, Opus 5, and other models, resolved within about an hour, 13:26-16:23 UTC), with claude.ai (99.4%), Claude Console (99.93%), Claude API (99.51%), Claude Code (99.44%), Cowork (99.43%), and Government (100%) all Operational.**

**As of the StatusGator check, user reports over the past 24 hours numbered 2**, from Maharashtra, India (9/8 13:16, not working) and Provence-Alpes-Côte d'Azur, France (9/7 19:29, down). **These read as scattered reports tied to specific regions and times rather than a pattern pointing to a broader service outage.** [Claude Status](https://status.claude.com) · [StatusGator](https://statusgator.com/services/claude)

## Ecosystem & Plugins

### Show GN: running GPT-6 Astra as the main model inside Claude Code (9/8)

**A third-party tool that lets you run GPT-6 Astra as Claude Code's main model while still mixing in Claude for subagents.** **It works as a local proxy that terminates TLS in front of the Anthropic API using its own CA (certificate authority) so it appears to be `api.anthropic.com`, connected via the `ANTHROPIC_BASE_URL` setting.**

**The upside is being able to mix and match models freely, but since the approach intercepts TLS with a self-issued CA, any organization with internal proxy policies or security requirements should first confirm this doesn't conflict with audit or compliance requirements before adopting it.** [GeekNews](https://news.hada.io/topic?id=33344)

## Minor Changes

All of the following are from **v2.1.265** (9/8).

- **A 1GB cap was added to how much tool-result data gets saved to disk**, and the conversation preview now shows whether a saved file was truncated.
- **Fixed an issue where Read, Write, and Edit rejected every file when running inside an AppContainer or a restricted-token sandbox**, caused by a change in how symlinks were resolved after permission checks.
- **Fixed an issue where `http`-type MCP servers that only support the legacy HTTP+SSE transport failed to connect at all**; it now falls back to SSE automatically as specified in the MCP spec.
- **[VSCode] Added an "Archive inactive sessions" setting** that automatically archives sessions with no activity for a set period (14 days by default).
- **Fixed an issue where syntax highlighting in permission prompts and messages occasionally dropped the character following a Ruby `?`, Erlang `$`, or Perl `$` sigil.**
