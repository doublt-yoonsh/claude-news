## 주요 신규 기능 & 실전 활용

### `--plugin-dir`로 플러그인 폴더 전체를 동적으로 관리합니다 (v2.1.265)

**`--plugin-dir`가 이제 플러그인 여러 개가 담긴 폴더 하나를 통째로 가리킬 수 있게 됐습니다.** **매니페스트를 가진 하위 폴더는 각각 개별 플러그인으로 로드되며, 세션이 실행되는 중에 하위 폴더를 추가하거나 삭제해도 그대로 반영**됩니다.

```bash
claude --plugin-dir ./team-plugins
# ./team-plugins/linter-helper/plugin.json
# ./team-plugins/deploy-checker/plugin.json
# 위처럼 하위 폴더마다 매니페스트가 있으면 각각 별도 플러그인으로 로드되고,
# 세션 도중 폴더를 넣거나 빼도 재시작 없이 즉시 반영됩니다
```

**팀 단위로 여러 플러그인을 묶어 배포하거나, 프로젝트별로 플러그인 구성을 바꿔가며 테스트하는 경우 하나하나 `--plugin-dir`를 지정하는 대신 폴더 단위로 관리할 수 있습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

## 보안/제한 이슈

### v2.1.265 회귀 버그로 게이트웨이·프록시 구성이 하루간 막혔다가 v2.1.266에서 수정 (9/8)

**문서화되지 않은 환경변수 `CLAUDE_CODE_USE_GATEWAY`는 원래 `ANTHROPIC_BASE_URL`과 `ANTHROPIC_AUTH_TOKEN`이 둘 다 설정된 경우가 아니면 무시됐는데, v2.1.265에서 이 변수 혼자서도 Cloud 게이트웨이 로그인을 강제로 요구하기 시작했습니다.** **그 결과 이 변수를 API 키·`apiKeyHelper`·커스텀 인증 헤더와 함께 설정해 둔 LLM 게이트웨이·프록시 구성에서는 모든 요청이 "Not signed in to the Cloud gateway" 오류로 실패**했습니다.

**같은 날 나온 v2.1.266에서 이 변수는 다시 단독으로는 무시되도록 되돌려졌으며, 별도 설정 변경 없이 업데이트만으로 정상화**됩니다. **자체 LLM 게이트웨이나 프록시를 앞단에 두고 Claude Code를 운영하는 팀이라면, 하루 사이라도 v2.1.265를 그대로 배포했다면 전체 요청이 막혔을 수 있으니 v2.1.266 이상으로 갱신을 확인할 필요가 있습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)
